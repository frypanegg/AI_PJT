# 프로젝트 인계 문서 (HANDOFF)

작성 2026-08-07. 이 프로젝트를 처음부터 지금까지 끌고 온 작업 세션의 기록이다.

`SYSTEM.md`가 **완성된 시스템이 어떻게 생겼는지**를 설명한다면, 이 문서는
**어떤 순서로 만들어졌고, 왜 그런 결정을 했으며, 어디서 막혔는지**를 남긴다.
같은 함정을 다시 밟지 않는 것이 목적이다.

---

## 1. 프로젝트 한 줄 요약

전직원 조직건강도 설문 결과(엑셀)를 부서장이 **스스로 해석할 수 있는 웹 리포트**로 바꾸되,
그 화면이 **평가 도구로 쓰이지 않도록** 데이터 처리부터 문장 생성까지 일관되게 막은 프로젝트.

사용자가 최종 확정한 표현:
> **"조직 간 비교가 아니라, 우리 조직에 대한 진단 결과"**
> **"우리 조직을 정확하게 이해하고, 건강하게 리딩할 수 있도록 지원하는 Agent"**

발표자: **사무계 / 포스코 / 곽경제** (인사문화실)

## 4. 핵심 의사결정과 이유

기능을 더할지 판단할 때마다 되돌아간 기준들이다. **되돌리기 전에 이유를 확인할 것.**

### 4.1 점수·등급·순위를 만들지 않는다

기획 단계(`06_guardrails.md`)부터의 원칙. 스키마에 총점·등급 필드 자체를 두지 않았다.
값이 있으면 언젠가 쓰이기 때문에, 아예 만들지 않는 쪽을 택했다.

### 4.2 부서 간 비교를 전면 배제 (프로젝트 중반 변경)

HR 부서로부터 **"부서 간 비교를 지양하라"**는 지침을 받았다. 초기 구현은 모든 해석을
전사 평균과 비교했는데("전사 평균 대비 +12.5%p"), 부서장이 자기 순위를 역산할 수 있어
사실상 부서 간 비교로 읽혔다.

문구만 바꾸지 않고 **비교 대상 산출 로직을 다시 설계**했다.

| 대상 | 1순위 | 폴백 |
| --- | --- | --- |
| 중분류 | 같은 대분류 안의 다른 중분류 평균 | — |
| 문항 | 같은 중분류 안의 다른 문항 평균 | 문항이 1개뿐이면 대분류 범위로 확장 |
| 공통 | | 비교 대상이 없으면 비교 없이 분포만 서술 |

**Admin 화면은 의도적 예외.** HR·경영진의 업무 목적이 부서 간 비교이므로 그 화면에만
남겼다. 같은 데이터라도 보는 사람에 따라 허용 범위를 다르게 둔 것이다.

### 4.3 개인 특정·문책 요청은 응답 자체를 거부

"부정 응답한 직급 찾아서 혼내야겠다" 같은 요청은 어떤 라우팅 경로로도 보내지 않고
즉시 거절한다. 데이터가 익명 집계라 특정이 불가능하다는 사실과 함께, 원인 상황을
보는 관점으로 되돌린다.

### 4.4 Streamlit → FastAPI 전환 (프로토타입 보존)

Streamlit으로 문구·화면 구성을 빠르게 검증한 뒤, 세션·업로드·감사로그 같은 운영형
요구가 확인되고 나서 FastAPI + SQLite로 재구축했다. Streamlit 버전을 지우지 않은 이유는
그것이 낭비가 아니라 검증 단계였기 때문. 두 버전은 포트가 달라 동시 구동된다.

해석 사전(`catalog.py`)과 문항 매핑은 **양쪽이 같은 파일을 참조**한다. 문구를 한 곳에서만
고치기 위해서다.

### 4.5 연도를 코드에 박지 않는다

`["2024","2025","2026"]`으로 하드코딩되어 있어, 내년 2027 시트가 추가된 파일을 올리면
조용히 무시될 상황이었다. 워크북의 시트 이름에서 4자리 연도를 자동 인식하고, 리포트
기준 연도는 DB에서 매번 조회하도록 바꿨다. 2027 시트를 넣은 4개년 파일을 실제로
업로드해 전 화면이 자동 확장되는 것을 확인했다.

### 4.6 더미데이터에 영역별 편차 주입

각 조직이 단일 성향으로 생성되어 있어, 한 조직 안 14개 영역이 서로 비슷했다. 그 결과
해석 문구가 대부분 "비슷한 수준입니다"로 나와 시연이 단조로웠다.

조직×중분류마다 목표 편차(±13~17%p)를 부여해 응답값 일부를 치환했다.
**"비슷한 수준" 비율 64% → 18%.** 편차는 대분류 안에서 대체로 상쇄되도록 설계해
조직 전체 평균과 Admin 화면의 비교 결과는 거의 변하지 않는다.

> 이 때문에 **6개 조직 중 3개는 합성 복제본이고, 영역 편차도 인위적**이다.
> 실제 설문 결과가 아니라는 점을 문서와 발표자료에 명시했다.

### 4.7 챗봇을 질문 의도별로 분기

키워드가 포함되기만 하면 같은 카드를 반복해, "가용자원이 한정적인데 어떻게 조율할까요?"
같은 후속 질문에도 요약만 되풀이했다. 길이와 의문 표현으로 조회와 질문을 구분해:

| 경로 | 조건 | 처리 |
| --- | --- | --- |
| 차단 | 개인 특정 + 징계 의도 | 응답 거부 |
| 로컬 | 짧은 키워드 조회 | DB 집계 + 해석 사전 (외부 호출 없음) |
| 근거 기반 LLM | 문장형 후속 질문 | 그 부서 수치를 컨텍스트로 전달 |
| 웹검색 | 진단과 무관한 일반론 | Tavily + OpenAI, 출처 링크 |

## 5. 겪은 문제와 해결

전부 실제로 밟은 것들이다. 코드에도 주석으로 남겼다.

### 5.1 앱 로직

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 리포트가 섹션 2에서 렌더링 중단 | 비중이 같은 항목들의 Plotly 차트가 완전히 동일해져 Streamlit이 `DuplicateElementId` 예외 발생 | 차트마다 명시적 `key=` 부여 |
| 다운로드 리포트에 첫 문답만 남음 | Starlette 세션이 **전체를 쿠키에 담는 구조** — AI 답변 두어 개면 4KB 한계 초과, 이후 저장이 조용히 실패 | 대화를 `chat_messages` 테이블로 이전, 쿠키엔 토큰만 |
| 전 페이지 500 에러 | Starlette 1.x에서 `TemplateResponse` 시그니처 변경 (`request`가 첫 인자) | 6곳 수정 |
| 업로드 시 `PermissionError` | `pd.ExcelFile`을 열어둔 채 `os.replace` | `with` 구문으로 닫기 |
| Gmail `501 HELO invalid` | Windows 로컬 호스트명에 공백 포함 | `smtp.ehlo("localhost")` 명시 |

### 5.2 시각화

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 막대 시작 위치가 문항마다 다름 | 문항 원문을 차트 y축 라벨로 써서 글자 길이만큼 밀림 | y축 라벨 제거, 문항을 HTML 제목으로 분리 → 32개 전부 952px |
| 좁은 구간 수치가 사라짐 | 스택 막대에서 글자가 안 들어가면 라이브러리가 라벨을 감춤. 바깥 배치도 미지원 | 11% 미만은 막대 오른쪽 고정폭 칸에. 웹앱은 렌더링 후 실제 폭 측정해 자동 이동 |
| 막대가 카드 밖으로 밀려남 | flexbox 기본값 `min-width:auto` | `min-width:0` + `overflow:hidden` |
| 한글이 음절 단위로 잘림 | 브라우저가 한글에 CJK 줄바꿈 규칙 적용 | `word-break: keep-all` (+ 긴 URL 대비 `overflow-wrap`) |
| 설명 문단이 막대보다 오른쪽까지 감 | 막대는 라벨 칸 114px을 예약하는데 문단은 카드 전체 폭 사용 | `max-width: calc(100% - 114px)` |

### 5.3 영상 제작

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| iframe으로 앱 제어 불가 | `file://` ↔ `http://` 교차 출처 | 플레이어 대신 **앱 페이지에 오버레이 직접 주입** |
| 페이지 이동 중 한 프레임 번쩍임 | 오버레이 설치가 `DOMContentLoaded`까지 미뤄져 첫 페인트에 없었음 | 즉시 설치 + `MutationObserver` 재시도 |
| 도입부에 로그인 화면 노출 | 앱이 먼저 그려진 뒤 검정을 덮음 | `__DEMO_START_BLACK`으로 첫 프레임부터 검정 |
| **HR 챕터 23초가 통째로 검정** | 오버레이 상태는 **출처별 저장**. `file://`에 갔다 앱으로 돌아올 때 남은 검정을 안 걷음 | 복귀 후 `fade_in()` 추가, 메모리 사본 병행 |
| 간지 위에 이전 자막·칩 겹침 | 칩·자막이 DOM상 커버보다 뒤 | `cover()` 진입 시 정리 |
| 간지가 검정 아래 깔려 빈 화면 | `fade_out` → `cover` 순서로 대기 | 커버 띄운 채 이동할 땐 검정 미사용 |
| 비동기 응답 대기가 일찍 끝남 | 메시지 개수만 세면 "생성 중…" 자리표시자에 걸림 | 자리표시자 소멸도 확인 |

### 5.4 PPTX 제작

**이 환경에는 LibreOffice도 PowerPoint도 없다.** 이미지 렌더 검수가 불가능해
`python-pptx`로 좌표를 재는 기하 검증(`qa_geometry.py`)을 만들어 대체했다.

| 항목 | 주의 |
| --- | --- |
| 슬라이드 크기 | 하드코딩 금지. 발표 양식은 26.67×15인치라 13.3인치 기준으로 재면 전부 오탐 |
| 서식 보존 | `text_frame.text` 대입 시 서식 소실 → **첫 run의 text만 교체** |
| 슬라이드 복제 | `<p:sldIdLst>` 재작성 시 `id` 속성 유실 → 저장 직전 재부여 |
| 인코딩 | 검증 스크립트가 cp949로 읽어 한글 깨짐 → `PYTHONUTF8=1` |
| 양식 겹침 | 목차 슬라이드 겹침 2건은 **원본에 이미 있는 배치** (원본 대조로 확인) |

## 7. 재생성 방법

### 앱 실행

```bash
cd Org_health_diag/webapp
pip install -r requirements.txt
uvicorn main:app --port 8000        # DB가 비면 기동 시 자동 적재
```

계정은 `streamlit_app/DEMO_GUIDE.md` 참조. 외부 API 키는 상위 폴더 `.env`
(`OPENAI_API_KEY`, `TAVILY_API_KEY`, `GMAIL`, `GMAIL_APP_PASSWORD`).

### 발표자료 PPTX

```bash
python docs/deck_build/build_skeleton.py   # 양식에서 17장 골격 (구조 먼저!)
python docs/deck_build/fill_content.py     # 텍스트 채우기
PYTHONUTF8=1 python docs/deck_build/qa_geometry.py 결과.pptx
```

구조 작업(복제·순서)을 **전부 끝낸 뒤** 내용을 채운다. 순서를 바꾸면 편집본이 복제된다.

### 시연 영상

```bash
# 1) 앱을 띄운 상태에서
cd docs/demo && python record_demo.py            # 약 4분 소요

# 2) 도입부 트림 + 목표 길이 배속 (길이를 재서 역산)
TRIM=4.45; SPEED=$(python -c "print(round((<원본초>-$TRIM)/150,5))")
ffmpeg -y -i 시연.mp4 -ss $TRIM -vf "setpts=PTS/$SPEED,format=yuv420p" \
  -r 30 -c:v libx264 -preset slow -crf 20 -movflags +faststart 시연_150s.mp4

# 3) 검수 (필수)
python docs/deck_build/find_flicker.py 시연_150s.mp4
python .claude/skills/web-demo-video/scripts/contact_sheet.py 시연_150s.mp4 out.png
```

- 배속을 **고정값으로 쓰지 말 것.** LLM 응답 대기가 매번 달라 원본 길이가 변한다.
- `-ss`는 `-i` **뒤에** 둔다. 앞에 두면 키프레임 탐색이라 위치가 어긋난다.
- 정상 검수 결과: 검정 구간이 챕터 전환용 0.7~2.2초짜리만, 밝은 섬광 0건.

영상과 발표자료에 공통 적용되어 있다.

- 타이틀: **"2026 조직건강도 진단 / AI Agent"**
- 부제: "부서장이 담당하는 **조직을 정확하게 이해**하고, **건강하게 리딩**할 수 있도록 지원하는 Agent"
- 하단: "포스코그룹 AI 활용 전문가 과정 · 프로젝트 과제 \<인사문화실 곽경제\>"
- 원칙: "핵심 원칙은 **조직간 비교가 아니라 우리 조직에 대한 진단 결과**"
- 클로징: "우리 조직을 정확하게 이해하고, 건강하게 리딩할 수 있도록 지원하는 Agent"
- 기대효과: "엑셀 Data로부터 부서별 진단 결과 이미지를 수작업으로 추출하던 작업을,
  자동으로 분석하여 Dash 보드 형태로 시인성 있게 만들어 진단 결과의 활용도를 높이고
  직책자들에게 정확하고 명확한 가이드를 제공할 수 있게 전환"

오탈자 3건은 화면에 그대로 나가는 부분이라 바로잡아 반영하고 고지했다
(`순위은→순위는`, `관활→관할`, `작업을.→작업을,`).

## 10. 사용자 선호 (관찰된 것)

- **결과만이 아니라 원인과 근거를 함께** 원한다. 추정으로 넘기지 말고 측정해서
  확인한 뒤 보고하는 방식이 잘 맞았다 (예: 프레임 밝기 측정으로 깜빡임 특정).
- 오탈자·근거 약한 수치를 그대로 두는 것을 원치 않는다. 다만 사용자가 쓴 문장을
  고칠 때는 **고쳤다고 명시**해야 한다.
- 근거가 약한 정량 수치(예: "30분→5분")는 빼는 쪽을 택했다.
- 커밋은 `webapp-redesign` 브랜치로만. main은 건드리지 않는다.
- 산출물은 파일로 직접 받길 원한다 (다운로드 카드).
