# 2026 조직건강도 진단 시스템 — 전체 문서

전직원 조직건강도 설문 결과를 부서장이 본인 조직 단위로 열람하고, 조직 운영 인사이트를
얻을 수 있도록 만든 Streamlit 기반 웹 데모. HR 관리자·경영진용 Admin 화면을 별도로 제공한다.

- **저장소**: `frypanegg/AI_PJT` → `Org_health_diag/`
- **실행 환경**: 로컬 PC 시연 전용 (웹 미배포)
- **총 코드량**: 약 2,000줄 (Python 10개 모듈)

---

## 1. 시스템 목적과 사용자

### 1.1 목적

부서장이 본인 담당 조직의 2026년 조직건강도 진단 결과를 웹 화면에서 스크롤로 확인하고,
전사 평균 대비 해석과 챗봇 대화를 통해 조직 운영 방향을 점검하도록 돕는다.

| HR 관리자 / 경영진 | Admin 버튼 + ID/PW | **전 부서 비교 + 접근 이력** |

## 3. 아키텍처

### 3.1 컴포넌트 구성

`app.py`가 오케스트레이터 역할을 하며, 4개 기능 컴포넌트(Skill)를 조합한다.

| 컴포넌트 | Skill 명 | 소스 | 처리 방식 |
| --- | --- | --- | --- |
| 데이터 해석 | `aggregate-skill` | `data.py`, `catalog.py`, `insights.py` | 규칙 기반 · 로컬 |
| 조직 챗봇 | `routing-skill` | `chatbot.py` | 규칙 기반 · 로컬 |
| Web Advisor | `search-skill` | `web_advisor.py` | **실시간 API** (Tavily + OpenAI) |
| 리포트 생성 | `export-skill` | `report_export.py` | 규칙 기반 · 로컬 |

> **중요**: 실시간 외부 API를 호출하는 컴포넌트는 `search-skill` 하나뿐이다.
> 나머지는 전부 로컬 규칙 기반이라 인터넷 연결 없이도 동작한다.

### 3.2 실행 흐름

```
로그인 → 집계·해석 → 챗봇 대화 → 리포트 조립 → 다운로드
```

### 3.3 라우팅 (`app.py` 하단)

세션 상태 3개 플래그로 4개 화면을 분기한다.

```python
if st.session_state.is_admin:              render_admin()        # 관리자 화면
elif st.session_state.authenticated:       render_report()       # 부서장 리포트
elif st.session_state.show_admin_login:    admin_login_page()    # 관리자 로그인
else:                                      login_page()          # 부서장 로그인
```

## 4. 데이터

### 4.1 원천 데이터

`organization_health_survey_2024_2026.xlsx` — 시트 3개(2024/2025/2026), 각 시트에
`응답형태 / 법인코드 / 회사명 / 조직명 / 32개 객관식 문항 / C1~C3 주관식` 컬럼.
1행은 컬럼 ID, 2행은 문항 원문, 3행부터 응답 데이터다.

**데이터 교체**: 관리자 화면(§6.2)에서 같은 형식의 엑셀을 업로드하면 이 기본 데이터를
대체해 전 화면에 적용된다. 업로드본이 없으면 아래 확장 더미 데이터를 사용한다.

### 4.2 6개 조직으로 확장

원본에는 조직이 3개뿐이라, `build_extended_dataset.py`로 포스코·포스코이앤씨 각 3개 부서
(총 6개)로 확장했다. 회사당 1개 유형은 다른 회사의 응답 패턴을 ±1단계 jitter(15% 확률)로
변형한 **합성 복제본**이다.

| 조직 유형 | 포스코 | 포스코이앤씨 |
| --- | --- | --- |
| 건강한 조직 | 철강사업실 (원본) | 철강설계실 (복제) |
| 중립 많은 변화기 조직 | 기술기획실 (원본) | 플랜트설계실 (복제) |
| 개선 신호 조직 | 경영혁신실 (복제) | 건설전략실 (원본) |

### 4.3 응답 척도 변환

5점 척도를 3분류로 집계한다 (`catalog.py`, `data.py::_bucket`).

| 원 응답 | 분류 |
| --- | --- |
| 전적으로 동의(공감)함 / 동의(공감)함 | **긍정** |
| 어느 쪽도 아님 | **중립** |
| 동의(공감)하지 않음 / 전혀 동의(공감)하지 않음 | **부정** |

### 4.4 문항 계층 구조

```
32개 객관식 문항  →  14개 중분류  →  2개 대분류
```

| 대분류 | 중분류 |
| --- | --- |
| 직원 몰입 수준 | 자발적 몰입, 방향성 제시, 리더에 대한 신뢰, 존경과 인정 |
| 회사 지원 수준 | 급여 및 복리후생, 개발기회, 실행환경 조성, 권한/임파워먼트, 협업, 업무/구조/프로세스, 교육훈련, 가용자원, 성과관리, DEIB |

문항ID→중분류 매핑은 원 기획 문서에 명시되어 있지 않아, 문항 원문을 근거로 이 프로젝트에서
구성했다 (`catalog.QUESTION_TO_MID`).

### 4.5 주관식 문항

| ID | 내용 | 처리 |
| --- | --- | --- |
| C1 | 긍정적 변화 / 자랑할 만한 조직문화 | 원문 미노출, 반복 경향 Top3만 |
| C2 | 개선이 필요한 문화·제도·정책 | 동일 |
| C3 | 일하는 방식 측면 개선점 | 동일 |

## 5. 핵심 분석 로직 — 전사 평균 대비 비교

모든 영역 해석은 **조직 자체 응답 중 어느 버킷이 큰지가 아니라, 같은 영역의 전사 평균과
비교**해 판단한다 (`insights.category_commentary`).

```python
diff = 조직 긍정 비중 - 전사 평균 긍정 비중

diff >= +3.0%p  →  "양호한 편"          (긍정 해석 카드)
diff <= -3.0%p  →  "관찰이 필요"        (부정 해석 카드)
그 외            →  "전사 평균과 비슷"   (중립 해석 카드)
```

임계값은 `insights.CATEGORY_DIFF_THRESHOLD = 3.0`. 절대 점수·등급은 산출하지 않으며
항상 상대 비교 문장으로만 표현한다. 이 로직은 리포트 카드/카테고리/문항 해석과 챗봇 답변,
Admin 우수·관심 부서 분류에 모두 동일하게 적용된다.

## 6. 화면 구성

### 6.1 부서장 리포트 (`render_report`)

좌측 사이드바에 5개 섹션 바로가기(앵커 링크)를 제공하고, 본문은 단일 스크롤로 이어진다.

| 섹션 | 내용 |
| --- | --- |
| **1. 2026 진단 요약** | 응답 인원·응답률·전체 긍정 비중 지표, 도넛 차트(중앙에 응답 인원 표기), 긍정/부정 Top3 영역 카드(비율바 + 팝오버 상세), 주관식 Top3, AI Executive Summary |
| **2. 카테고리별 2026 결과** | 대분류 2개 탭. 중분류마다 **미니 막대차트 → 바로 아래 해석 문장** 반복. 전사 평균 긍정 비중을 검은 마름모로 표시 |
| **3. 32개 문항별 근거** | 중분류 필터 + 정렬 기준(긍정/부정 높은 순). 문항마다 **문항 원문을 Y축 라벨로 쓴 미니차트 → 해석** 반복 |
| **4. 3개년 변화 분석** | 긍정/중립/부정을 **각각 독립 스케일의 3개 차트**로 분리. 2024→2026 변화 순위(개선 상위 5개 / 관찰 필요 하위 5개)를 큰 숫자로 표기. 중분류 선택 시 해당 영역 추이 표시 |
| **5. AI 조직 운영 인사이트** | 건강도 해석, 주의 신호, 30일 대화 주제, 질문 예시, **조직운영 챗봇**, 리포트 다운로드 |

**차트 설계 원칙**
- 3개년 추이는 변동폭이 작아 Y축을 데이터 범위에 맞춰 확대 (`padded_y_range`, 0~100 고정 아님)
- 색상: 긍정 `#3E8E5A`, 중립 `#B0B7C3`, 부정 `#D9534F` (전 화면 통일)
- 임원 가독성을 위해 전체 폰트를 120%로 확대

### 6.2 관리자 화면 (`render_admin`)

| 섹션 | 내용 |
| --- | --- |
| **1. Raw Data 업로드** | 설문 원본 엑셀(.xlsx)을 업로드해 전체 시스템의 분석 데이터를 교체. 현재 사용 중인 데이터 표시, 형식 안내, 검증 결과 요약, 기본 더미 데이터로 되돌리기 |
| **2. 부서별 2026 결과 비교** | 6개 부서를 전사 평균 대비 ±3%p 기준으로 🟢 우수 / 🔴 관심 필요 / ⚪ 평균 분류. 표 + 막대차트(전사 평균 기준선) |
| **3. 부서별 2024–2026 변화 추이** | 6개 부서 긍정 비중 라인차트 + 부서별 3개년 변화폭 표 |
| **4. 부서장별 접근 이력** | 회사명 · 부서명 · 조직장명 · 로그인 이력 · 챗봇 채팅 이력 · 보고서 다운로드 이력 (횟수 + 최근 시각) |

#### Raw Data 업로드 동작

업로드 파일은 저장 전에 `data.validate_workbook()`으로 검증한다.

| 검사 | 실패 시 |
| --- | --- |
| 파일이 열리는 엑셀인가 | **거부** — 기존 데이터 유지 |
| `2024`·`2025`·`2026` 시트가 모두 있는가 | **거부** |
| 1행에 `회사명`·`조직명` 컬럼이 있는가 | **거부** |
| 32개 문항ID 중 인식되는 것이 있는가 | **거부** |
| 조직명이 등록 부서와 하나라도 일치하는가 | **거부** |
| 32개 문항이 모두 있는가 | 경고 (사용은 가능) |
| 등록 부서가 모두 파일에 있는가 | 경고 (누락 부서는 결과 미표시) |

- 검증을 통과한 파일만 `dummy_data/uploaded_survey.xlsx`로 저장되며(임시파일 → `os.replace`
  원자적 교체), 실패 시 기존 데이터는 손상되지 않는다.
- 업로드본이 존재하면 부서장 리포트를 포함한 **전 화면이 이 파일을 사용**한다
  (`data.active_excel_path()`).
- 데이터 캐시는 `(경로, 수정시각)`을 키로 쓰므로 파일 교체 시 자동으로 다시 읽는다.
- 업로드 파일은 실제 설문 응답을 담을 수 있어 `.gitignore`로 커밋을 차단한다.

## 7. 인증과 접근 로그 (`auth.py`)

### 7.1 부서장 인증

조직 LOV 선택 + 생년월일 6자리. URL 파라미터(`?org=ss`)로 조직을 사전 선택한 개인화 링크를
메일로 배포하는 시나리오를 지원한다. 인증코드는 화면에 노출하지 않고 `DEMO_GUIDE.md`로만 전달.

`ORG_REGISTRY`에 조직별 `company / org / manager_name / birth_code / target_headcount` 보관.

### 7.2 관리자 인증

로그인 화면 우측 상단 **🔐 Admin** 버튼 → 별도 ID/PW (`ADMIN_CREDENTIALS`).
부서장 인증과 완전히 분리된 경로다.

### 7.3 접근 로그

모든 이벤트를 `logs/access_log.csv`에 기록한다 (`timestamp, org_key, org, event`).

| 이벤트 | 발생 시점 |
| --- | --- |
| `login_success` / `login_failed` | 부서장 로그인 시도 |
| `logout` | 로그아웃 |
| `chat_message` | 챗봇 질문 전송 (빠른 버튼 포함) |
| `report_download` | 리포트 HTML 다운로드 |

`manager_activity_table()`이 이 로그를 부서장별로 집계해 Admin 화면 3번 표를 만든다.

## 8. 챗봇 (`chatbot.py` + `web_advisor.py`)

### 8.1 라우팅 우선순위

| 순위 | 조건 | 처리 |
| --- | --- | --- |
| 1 | 인사말 키워드 | 환영 메시지 |
| 2 | 다음 단계 키워드 (`다음`, `30일`…) | 부정 Top3 영역의 권장 대화 방향 |
| 3 | 요약 키워드 (`요약`, `전체`…) | 전체 비중 + Top3 요약 |
| 4 | 14개 중분류 키워드 매칭 | 전사 평균 대비 해석 + 질문 예시 (로컬) |
| 5 | 매칭 실패 | **Web Advisor 위임** (일반 리더십 질문) |
| 6 | Web Advisor 실패/비활성 | 14개 영역 목록 안내 |

### 8.2 Web Advisor (search-skill)

일반 리더십/조직관리 질문(예: "말 안 듣는 직원 관리 방법")을 처리한다.

```
질문 → Tavily 웹검색 (상위 4건) → OpenAI(gpt-4.1-mini)로 종합 → 답변 + 출처 링크
```

**개인정보 보호**: 외부로 전송되는 것은 사용자가 입력한 질문 문장뿐이며, 조직의 진단
데이터는 전달되지 않는다.

**Fail-safe**: API 키 미설정이거나 호출 실패 시 항상 조용히 `None`을 반환하고 예외를 밖으로
던지지 않는다. 상위 로직이 자동으로 오프라인 안내로 대체하므로 키 없이도 앱은 정상 동작한다.

**시스템 프롬프트 원칙**: 개인·조직 평가 금지, 징계/처벌적 관리 권장 금지, 처방 대신 점검
방향 제시, 점수·등급·순위 표현 금지, 검색 결과에 없는 내용 생성 금지.

## 12. 알려진 제한사항

- **웹 미배포 로컬 데모**이며, 인증은 SSO가 아닌 조직+생년월일 데모 로직이다. 실 서비스
  전환 시 사내 SSO와 권한 매핑 테이블로 교체해야 한다.
- **AI 해석 문장은 실시간 LLM 호출이 아니다.** 문항 해석 사전 기반 규칙 로직으로 생성한
  예시이며, 실제 적용 시 `03_ai_agent_design.md`의 Multi-Agent 파이프라인(LLM 기반
  Report Writer / Guardrail Reviewer)으로 교체하는 것을 전제로 한다.
- **챗봇의 14개 영역 답변도 규칙 기반**이다. 웹검색 경로만 실제 LLM을 사용한다.
- **응답률의 "대상 인원"은 가정치**다. 더미 데이터에 없는 값이라 `auth.py::target_headcount`로
  임의 지정했고, 화면에도 "가정치"로 표기한다.
- **6개 조직 중 3개는 합성 복제 데이터**다(§4.2). 실제 서로 다른 두 회사의 응답이 아니다.
- **리포트 메일 발송 미지원** — HTML 다운로드까지만 제공한다.
- 조직장명(`manager_name`)은 데모용 가상 인물이다.
- **업로드 데이터는 조직 목록을 바꾸지 않는다.** 부서 구성은 `auth.ORG_REGISTRY`에
  하드코딩되어 있어, 등록되지 않은 조직명이 파일에 있어도 화면에 나타나지 않는다.
  새 부서를 추가하려면 레지스트리도 함께 수정해야 한다.
- **업로드본은 서버 파일 1개로 관리**된다. 여러 관리자가 동시에 사용할 경우 마지막
  업로드가 전체에 적용되며, 버전 이력은 남지 않는다.
